# 配置与使用说明

本手册针对本项目适配的 Windows Desktop ZCode 3.14.4.7912。
仍然使用原版 ZCode 的快捷方式、会话和模型设置。插件负责选择提示词文件，
宿主桥接补丁负责在普通本地主会话中替换客户端构造的 system 内容。

当前插件名为 `zcode-unrestricted`，版本 0.3.0。从旧名 `dsh-unrestricted` 升级时，
关闭 ZCode 后运行新的 `install.cmd`，再按新名称打开插件配置。
安装器迁移用户级开关和文件选项，复制旧默认正文到尚不存在的新默认文件，
保留旧正文和备份。旧工作区专属设置不会自动改写，需要在相应 Workspace 范围重新选择文件和开关。

以下个人路径是本机示例。私人 `system.md` 与 `docs/test.md` 等草稿保留本地，由 Git
和公共 ZIP 排除。新用户可先留空使用默认示例，或指定包内 `example-system.md` 的实际路径。

## 1. 先分清三个位置

| 位置 | 本机示例 | 用途 |
| --- | --- | --- |
| 本项目开发目录 | `D:\Work\Zcode\zcode-unrestricted` | 保存插件源文件、安装脚本、文档和测试；不是另一套 ZCode。 |
| ZCode 当前会话的工作区 | 例如 `D:\Work\Zcode` | 你在 ZCode 中打开的项目，决定工作区配置和相对路径的解析位置。 |
| 安装后的插件数据目录 | `C:\Users\xiaoh\.zcode\cli\plugins\data\zcode-unrestricted@inline` | 保存默认提示词 `system.md` 和最近一轮状态。 |

开发目录与会话工作区可以不同。不要因为提示词放在开发目录，就假定 ZCode
当前也以这个目录为工作区。修改哪个文件会生效，取决于高级配置实际选择的文件。
完整目录解释见 [项目目录说明](project-layout.md)。

## 2. 高级配置怎么填

这里的“高级配置”位于插件详情中的 **高级信息 → 配置**。
当前对应 UI 源码把 `file` 类型配置渲染为普通文本输入框，并没有自动把正文保存成文件。

1. 打开原版 ZCode 的设置或插件管理，进入已安装插件，找到 **zcode-unrestricted**。
2. 在范围选择器中选择 **用户 / User**，或选择需要设置的具体 **工作区 / Workspace**。
3. 打开插件详情，展开 **高级信息**，找到 **配置** 下的 **系统提示词文件**。
4. 清除原有的整段提示词，只填文件的实际绝对路径。使用本项目改写的提示词时填：

   ```text
   D:\Work\Zcode\zcode-unrestricted\docs\test.md
   ```

5. 点击 **保存配置**，等待保存成功。只输入、不保存，不会写入实际配置。
6. 确认插件开关开启，回到目标工作区发送下一轮普通消息。
7. 运行开发目录或解压交付包里的 `status.cmd`，检查最近一轮状态。

该输入框的配置键叫 `promptFile`，值是**路径**；提示词正文保存在路径对应的文件里。
路径有空格也直接填写，不加外层引号，不加 `@`，不粘贴 JSON 或 Markdown 代码围栏。
建议填写展开后的实际绝对路径，不依赖 `~`、`%USERPROFILE%` 等缩写的展开。

提示词文件必须存在、非空、能按 UTF-8 解码，大小不超过 256 KiB。
读取失败时，本轮回退到原生 system，不会把输入框里的文字当作提示词直接注入。

例如，本轮工作区是 `D:\Work\Zcode` 时，相对路径 `docs\test.md` 会指向
`D:\Work\Zcode\docs\test.md`，不是本项目内的文件。第一次配置建议使用上面的绝对路径。

## 3. User 与 Workspace 怎么选择

| 范围 | 适用情况 | 行为 |
| --- | --- | --- |
| 用户 / User | 希望多个本地项目默认使用同一份提示词 | 保存用户级默认开关和文件选择。 |
| 工作区 / Workspace | 只在某个项目使用，或该项目需要不同提示词 | 该工作区的显式配置覆盖 User 默认。 |

本项目使用原版 ZCode 的配置合并，没有另设第二套开关。父目录项目配置也可能参与合并。
因此，User 已开启不保证每个工作区最终都开启；User 修改路径后，工作区已有的路径覆盖
也不会自动消失。

如果修改 User 后目标项目仍使用旧值，切到那个工作区范围检查开关和文件字段。
需要恢复 User 的值时，使用界面提供的 **恢复 User 默认 / 恢复继承值** 功能并保存。

**留空与恢复继承不同：** `promptFile` 保存为空字符串时，桥接使用插件默认 `system.md`；
清除工作区覆盖键、恢复继承时，则继续使用 User 已设置的路径。

## 4. 选择默认文件还是自己的文件

### 使用自己的文件

把正文保存到固定的 UTF-8 文件，在高级配置里选择它。之后直接编辑该文件，
保存后下一轮加载，无需重装补丁。文件移动或删除后，必须更新路径。

本项目的 `docs/test.md` 是一份 ZCode 编程助手提示词草稿。它不会被 ZCode 自动扫描加载，
也不会因为放在 `docs` 里而获得特殊作用；上述文件选择才决定是否使用它。

### 使用安装后的默认文件

在适用范围内把 `promptFile` 留空并保存，桥接读取：

```text
C:\Users\xiaoh\.zcode\cli\plugins\data\zcode-unrestricted@inline\system.md
```

双击项目根目录的 `edit-prompt.cmd` 可用记事本编辑这个默认文件。
其他 Windows 用户的路径以其实际用户目录为准。

`edit-prompt.cmd` **始终打开默认文件**。若高级配置指向 `docs/test.md` 或其他文件，
运行该脚本不会切换选择，也不会编辑当前选中的自定义文件。

首次安装会从开发包的 `plugins/zcode-unrestricted/prompts/system.md` 初始化默认文件；
没有该文件时使用 `example-system.md`。默认文件已经存在时，重新安装会保留它。
因此修改开发包里的模板、再运行安装器，不会覆盖已经编辑的默认正文。

## 5. 如何确认本轮读取结果

双击 `status.cmd` 可查看状态。它只读检查文件和最近一轮记录，不会启动模型会话。

| 字段或值 | 含义 |
| --- | --- |
| `state: mounted` | Agent、桥接和 binding 的磁盘文件与安装记录校验一致。 |
| `state: legacy_mounted` | 旧名 0.2.0 的文件校验一致，可以继续使用；关闭 ZCode 后运行安装器可迁移为新名称。 |
| `state: unmounted` | 磁盘文件未完整挂载或校验不一致；常见于未安装、升级覆盖或文件被改动。 |
| `userEnabled: true` | 用户级配置注册并开启了插件，不包含工作区覆盖后的最终判断。 |
| `lastTurn.state: active` | 最近处理的一轮成功读取提示词并建立覆盖快照。 |
| `lastTurn.state: off` | 最近处理的一轮在最终配置下关闭了覆盖。 |
| `lastTurn.state: error` | 最近处理的一轮解析失败，并回退到原生基线；查看 `code`。 |
| `lastTurn.workspace` | 这份最近一轮记录对应的工作区。 |
| `lastTurn.observedAt` | 记录时间。尚未发送新一轮时，记录可能仍是旧状态。 |
| `lastTurn.revision` | 最近一轮解码后的正文摘要，不记录正文内容。 |
| `promptFile`、`promptBytes`、`promptHash` | 检查器展示的**默认文件**位置、字节数和摘要，不代表高级配置选择的有效文件。 |

状态记录由本插件的适用会话共享，多个工作区或窗口都在使用时，后处理的一轮会更新它。
检查时同时核对工作区和时间，避免把其他窗口的记录当作当前会话。

`active` 证明桥接解析成功，并不是供应商最终收到请求的抓包证据，也不保证某种回答行为。
可先用普通的语气、回答语言或格式要求验证效果；不要仅根据模型自述判断是否替换。
关闭插件或修改文件后，需要发送下一轮才能产生新记录。进行中的一轮保持原快照。

## 6. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| `mounted`，但 `lastTurn` 为 `resolve_failed` | `promptFile` 是否被填成正文、是否带外层引号、是否是无法读取的路径。该错误码是一般解析失败，不能单凭它确定唯一原因。 |
| `ENOENT` | 文件或插件清单不存在；尤其注意相对路径解析到了哪个工作区。 |
| `empty_prompt` | 文件为空或只有空白字符。 |
| `invalid_utf8` | 文件不是有效 UTF-8；用编辑器明确另存为 UTF-8。 |
| `oversize` | 文件超过读取上限；提示词正文上限为 256 KiB。 |
| 用户开关已开启，本轮仍是 `off` | 目标工作区或父目录项目配置是否关闭了插件；检查记录是否是最新一轮。 |
| 修改了提示词，回复仍像旧行为 | 修改的是否是实际选中的文件；是否已保存并发送下一轮；是否在旧会话上下文中重复比较。 |
| 改了 `docs/test.md`，默认 `promptHash` 没变化 | 正常：该字段只检查默认 `system.md`。自定义文件对应的是本轮 `revision`。 |
| 更新 ZCode 后 `unmounted` | 可能是更新覆盖补丁。需要核对新版本适配，不能用旧 Agent 备份覆盖新版。 |
| 插件详情显示没有普通技能、MCP 或 Hook 组件 | 此插件通过单独的宿主桥接实现替换；是否挂载以状态检查为准。 |

首次安装补丁需要完全退出再启动 ZCode，使新的 Agent 文件被加载。
安装完成后的文件选择、正文修改和开关变化按下一轮热加载，无需每次重装。

## 7. 手动查看配置时，字段在哪里

优先使用原版 UI。确需检查 JSON 时，用户级文件通常是
`C:\Users\xiaoh\.zcode\cli\config.json`，工作区配置位于相应项目的 `.zcode/config.json`。
父目录的项目配置也可能参与合并。

相关字段形状如下。这只是需要合并的局部示例，**不能用它替换整份配置文件**，
否则会丢失模型、凭据、其他插件和现有设置：

```json
{
  "plugins": {
    "enabledPlugins": {
      "zcode-unrestricted@inline": true
    },
    "options": {
      "zcode-unrestricted@inline": {
        "promptFile": "D:\\Work\\Zcode\\zcode-unrestricted\\docs\\test.md"
      }
    }
  }
}
```

安装器负责注册 `plugins.dirs`，已有注册应保留。UI 的路径输入框使用单个反斜杠，
JSON 字符串中才需要双反斜杠转义。配置里存路径，文件里存正文。

## 8. 关闭与恢复

- 暂时关闭：在适用 User 或 Workspace 范围关闭插件，再发送下一轮。
- 恢复原版 Agent 文件：完全退出 ZCode，再运行根目录 `uninstall.cmd`。
- 卸载后提示词、备份和安装记录会保留；这些保留文件本身不会继续注入。
- 普通本地主会话之外的子代理、工作流、远程 Agent 和标题/摘要专用请求不在首版范围内。

实现原理见 [设计说明](design.md)，已有离线验证范围见 [验证记录](validation.md)。
